# SPARC Specification: Ground Truth Management System

## 1. System Overview

### 1.1 Purpose
The Ground Truth Management System provides comprehensive capabilities for creating, validating, and exporting ground truth data for AI/ML model training and validation. It serves as the authoritative source of validated detection data for VRU (Vulnerable Road User) recognition systems.

### 1.2 Scope
- Automated ground truth generation using pre-trained models
- Manual ground truth creation and editing
- Validation workflows and quality control
- Statistical analysis and reporting
- Export capabilities for ML training pipelines
- Integration with annotation system

### 1.3 Key Components
- Automated detection pipeline
- Manual validation interface  
- Statistical analysis engine
- Export format handlers
- Quality assurance workflows
- Performance metrics tracking

## 2. Functional Requirements

### 2.1 Ground Truth Generation

#### FR-GT-2.1.1 Automated Detection
- **Description**: System shall automatically generate ground truth data using pre-trained ML models
- **Priority**: High
- **Acceptance Criteria**:
  - Process videos through YOLOv8 detection pipeline
  - Generate bounding boxes with confidence scores
  - Classify VRU types (pedestrian, cyclist, motorcyclist, wheelchair, scooter)
  - Store temporal information (frame number, timestamp)
  - Handle multiple detection models (YOLOv8n, YOLOv8s, YOLOv8m)
  - Support GPU acceleration when available
- **Performance Requirements**:
  - Process video at 2x real-time speed minimum
  - Memory usage < 4GB for standard videos
  - Batch processing for multiple videos
- **Input Validation**:
  - Video format validation (MP4, AVI, MOV)
  - Resolution limits (minimum 480p, maximum 4K)
  - Duration limits (maximum 2 hours per video)

#### FR-GT-2.1.2 Confidence Scoring
- **Description**: System shall provide confidence scores for all generated detections
- **Priority**: High
- **Acceptance Criteria**:
  - Confidence scores normalized to 0-1 range
  - Configurable confidence thresholds per VRU type
  - Low-confidence detections flagged for manual review
  - Confidence distribution analytics
  - Model performance tracking per confidence range
- **Business Rules**:
  - Default confidence threshold: 0.7 for pedestrians, 0.6 for cyclists
  - Detections below threshold marked for validation
  - High confidence detections (>0.9) auto-approved with review option

#### FR-GT-2.1.3 Temporal Consistency
- **Description**: System shall maintain temporal consistency across video frames
- **Priority**: Medium
- **Acceptance Criteria**:
  - Object tracking across consecutive frames
  - Temporal smoothing for bounding box coordinates
  - Detection of appearing/disappearing objects
  - Handling of occlusions and re-appearances
  - Frame-to-frame association algorithms

### 2.2 Manual Ground Truth Creation

#### FR-GT-2.2.1 Manual Annotation Interface
- **Description**: System shall provide tools for manual ground truth creation
- **Priority**: High
- **Acceptance Criteria**:
  - Draw bounding boxes on video frames
  - Assign VRU classifications
  - Set difficulty levels (easy, medium, hard)
  - Mark occlusion and truncation status
  - Add contextual notes and comments
  - Support keyboard shortcuts for efficiency
- **Usability Requirements**:
  - Sub-pixel accuracy for bounding boxes
  - Snap-to-edge assistance
  - Copy/paste annotations across frames
  - Undo/redo functionality (50 steps)

#### FR-GT-2.2.2 Batch Operations
- **Description**: System shall support batch operations for efficiency
- **Priority**: Medium
- **Acceptance Criteria**:
  - Batch import from external annotation tools
  - Bulk validation of multiple annotations
  - Batch export to various formats
  - Mass updates of classification labels
  - Bulk deletion with confirmation
- **Format Support**:
  - Import: COCO JSON, YOLO TXT, Pascal VOC XML
  - Export: COCO JSON, YOLO TXT, Pascal VOC XML, TensorFlow Records

### 2.3 Validation and Quality Control

#### FR-GT-2.3.1 Multi-Stage Validation
- **Description**: System shall implement multi-stage validation workflow
- **Priority**: High
- **Acceptance Criteria**:
  - Three-stage process: Generated → Reviewed → Validated
  - Role-based validation permissions
  - Validation comments and feedback
  - Rejection reasons and correction requests
  - Re-validation after corrections
- **Validation Stages**:
  - **Stage 1 (Generated)**: Auto-generated by ML models
  - **Stage 2 (Reviewed)**: Human reviewed for accuracy
  - **Stage 3 (Validated)**: Final approval for training use
  - **Stage 4 (Archived)**: Historical versions maintained

#### FR-GT-2.3.2 Quality Metrics
- **Description**: System shall calculate and track quality metrics
- **Priority**: High
- **Acceptance Criteria**:
  - Inter-annotator agreement (IoU-based)
  - Precision and recall per VRU type
  - Temporal consistency scores
  - Coverage analysis (% of frames with annotations)
  - Distribution analysis (class balance, spatial distribution)
- **Metrics Calculations**:
  - IoU (Intersection over Union) for bounding box accuracy
  - Cohen's Kappa for inter-annotator agreement
  - F1 scores per class and overall
  - Temporal stability metrics

#### FR-GT-2.3.3 Automated Quality Checks
- **Description**: System shall perform automated quality assurance
- **Priority**: Medium
- **Acceptance Criteria**:
  - Detect overlapping bounding boxes
  - Flag unusually large/small boxes
  - Identify temporal inconsistencies
  - Check for missing annotations in sequences
  - Validate classification consistency
- **Quality Rules**:
  - Bounding box aspect ratio validation
  - Minimum/maximum size constraints
  - Temporal jitter detection (>10% movement between frames)
  - Class transition validation (pedestrian → cyclist flags for review)

### 2.4 Statistical Analysis and Reporting

#### FR-GT-2.4.1 Dataset Statistics
- **Description**: System shall provide comprehensive dataset statistics
- **Priority**: Medium
- **Acceptance Criteria**:
  - Class distribution (counts and percentages)
  - Temporal distribution across video timeline
  - Spatial heat maps of detection locations
  - Size distribution of bounding boxes
  - Confidence score distributions
- **Statistical Metrics**:
  - Mean, median, std deviation for all numeric fields
  - Histograms for size, confidence, temporal distributions
  - Correlation analysis between different metrics

#### FR-GT-2.4.2 Validation Progress Tracking
- **Description**: System shall track validation progress and productivity
- **Priority**: Medium
- **Acceptance Criteria**:
  - Progress tracking per video and project
  - Validator productivity metrics
  - Time estimation for completion
  - Bottleneck identification in validation pipeline
  - Quality trends over time
- **Progress Metrics**:
  - Annotations per hour per validator
  - Validation accuracy (% requiring corrections)
  - Average time per annotation by complexity

### 2.5 Export and Integration

#### FR-GT-2.5.1 ML Training Export
- **Description**: System shall export ground truth in ML-ready formats
- **Priority**: High
- **Acceptance Criteria**:
  - COCO JSON format for object detection
  - YOLO format for YOLO-family models
  - TensorFlow Records for TensorFlow models
  - Custom JSON format with metadata
  - Split datasets (train/validation/test)
- **Export Configuration**:
  - Configurable train/val/test splits (default 70/20/10)
  - Filter by validation status
  - Include/exclude difficult examples
  - Class-balanced sampling options

#### FR-GT-2.5.2 Analytics Integration
- **Description**: System shall integrate with analytics and reporting systems
- **Priority**: Medium
- **Acceptance Criteria**:
  - REST API for statistics retrieval
  - Real-time metrics via WebSocket
  - Dashboard data feeds
  - Custom report generation
  - Data pipeline integration

### 4.1 Ground Truth Generation

```yaml

  /api/videos/{video_id}/ground-truth/generate:
    post:
      summary: Generate ground truth for video
      parameters:
        - name: video_id
          in: path
          required: true
          schema:
            type: string
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object

                    type: string

                  default: [pedestrian, cyclist, motorcyclist]

                  type: integer
                  minimum: 1
                  maximum: 30
                  default: 1

        202:
          description: Processing started
          content:
            application/json:
              schema:
                type: object

                    type: string

                    type: string

                    type: integer
                    description: Estimated processing time in seconds

          description: Invalid parameters
        404:
          description: Video not found
        409:
          description: Ground truth already exists
```

## 5. Database Schema Requirements

### 5.1 Enhanced Ground Truth Objects Table
```sql
CREATE TABLE ground_truth_objects (
    id VARCHAR(36) PRIMARY KEY DEFAULT (UUID()),
    video_id VARCHAR(36) NOT NULL,
    detection_id VARCHAR(50) UNIQUE, -- Format: DET_[VRU_TYPE]_[SEQUENCE]
    frame_number INTEGER NOT NULL,
    timestamp FLOAT NOT NULL, -- Seconds from video start
    
    -- VRU Classification
    vru_type ENUM('pedestrian', 'cyclist', 'motorcyclist', 'wheelchair', 'scooter', 'animal', 'other') NOT NULL,
    
    -- Bounding Box (normalized coordinates 0-1)
    bbox_x FLOAT NOT NULL CHECK (bbox_x >= 0 AND bbox_x <= 1),
    bbox_y FLOAT NOT NULL CHECK (bbox_y >= 0 AND bbox_y <= 1),  
    bbox_width FLOAT NOT NULL CHECK (bbox_width > 0 AND bbox_width <= 1),
    bbox_height FLOAT NOT NULL CHECK (bbox_height > 0 AND bbox_height <= 1),
    
    -- Detection Metadata
    confidence FLOAT CHECK (confidence >= 0 AND confidence <= 1),
    model_name VARCHAR(50), -- yolov8n, yolov8s, etc.
    model_version VARCHAR(20),
    
    -- Quality Indicators
    difficult BOOLEAN DEFAULT FALSE,
    occluded BOOLEAN DEFAULT FALSE,
    truncated BOOLEAN DEFAULT FALSE,
    blurred BOOLEAN DEFAULT FALSE,
    
    -- Validation Workflow
    validation_status ENUM('generated', 'reviewed', 'validated', 'rejected') DEFAULT 'generated',
    validated_at TIMESTAMP NULL,
    validator_id VARCHAR(36),
    validation_notes TEXT,
    
    -- Temporal Tracking
    track_id VARCHAR(50), -- For multi-frame object tracking
    track_confidence FLOAT, -- Tracking algorithm confidence
    
    -- Audit Fields
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by VARCHAR(36), -- System or user ID
    
    -- Foreign Keys
    FOREIGN KEY (video_id) REFERENCES videos(id) ON DELETE CASCADE,
    
    -- Performance Indexes
    INDEX idx_gt_video_frame (video_id, frame_number),
    INDEX idx_gt_video_timestamp (video_id, timestamp),
    INDEX idx_gt_video_vru_type (video_id, vru_type),
    INDEX idx_gt_validation_status (validation_status),
    INDEX idx_gt_validator (validator_id),
    INDEX idx_gt_track_id (track_id),
    INDEX idx_gt_confidence (confidence),
    INDEX idx_gt_model (model_name, model_version),
    INDEX idx_gt_temporal_range (timestamp, track_id),
    INDEX idx_gt_validation_workflow (video_id, validation_status, validated_at),
    INDEX idx_gt_quality_flags (difficult, occluded, truncated),
    
    -- Spatial Index for bounding box queries
    INDEX idx_gt_spatial_bbox (bbox_x, bbox_y, bbox_width, bbox_height),
    
    -- Composite indexes for common queries
    INDEX idx_gt_video_validation_vru (video_id, validation_status, vru_type),
    INDEX idx_gt_frame_confidence (frame_number, confidence),
    INDEX idx_gt_validator_performance (validator_id, validation_status, validated_at)
);
```

### 5.2 Ground Truth Processing Jobs Table
```sql
CREATE TABLE ground_truth_processing_jobs (
    id VARCHAR(36) PRIMARY KEY DEFAULT (UUID()),
    video_id VARCHAR(36) NOT NULL,
    job_type ENUM('generation', 'validation', 'export') NOT NULL,
    status ENUM('queued', 'processing', 'completed', 'failed', 'cancelled') DEFAULT 'queued',
    
    -- Processing Configuration
    config JSON NOT NULL, -- Model settings, thresholds, etc.
    
    -- Progress Tracking
    progress_percentage FLOAT DEFAULT 0.0 CHECK (progress_percentage >= 0 AND progress_percentage <= 100),
    frames_processed INTEGER DEFAULT 0,
    total_frames INTEGER,
    detections_generated INTEGER DEFAULT 0,
    
    -- Timing Information
    started_at TIMESTAMP NULL,
    completed_at TIMESTAMP NULL,
    processing_duration INTEGER, -- Seconds
    estimated_remaining INTEGER, -- Seconds
    
    -- Results and Errors
    result_summary JSON, -- Statistics about results
    error_message TEXT,
    retry_count INTEGER DEFAULT 0,
    max_retries INTEGER DEFAULT 3,
    
    -- Resource Usage
    cpu_time_used INTEGER, -- CPU seconds
    memory_peak_mb INTEGER,
    gpu_memory_used_mb INTEGER,
    
    -- Audit Fields
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by VARCHAR(36),
    
    -- Foreign Keys
    FOREIGN KEY (video_id) REFERENCES videos(id) ON DELETE CASCADE,
    
    -- Indexes
    INDEX idx_job_video_type (video_id, job_type),
    INDEX idx_job_status (status),
    INDEX idx_job_created (created_at),
    INDEX idx_job_progress (status, progress_percentage)
);
```

```sql
    video_id VARCHAR(36) NOT NULL,
    metric_type ENUM('iou_accuracy', 'class_consistency', 'temporal_stability', 'coverage', 'inter_annotator_agreement') NOT NULL,
    
    -- Metric Values
    metric_value FLOAT NOT NULL,
    threshold_passed BOOLEAN,
    quality_grade ENUM('A', 'B', 'C', 'D', 'F'),
    
    -- Context Information
    vru_type VARCHAR(20), -- Specific VRU type or 'all'
    frame_range_start INTEGER,
    frame_range_end INTEGER,
    sample_size INTEGER, -- Number of annotations in calculation
    
    -- Calculation Details
    calculation_method VARCHAR(100),
    reference_data JSON, -- Ground truth or other annotations used as reference
    detailed_scores JSON, -- Breakdown of scores
    
    -- Metadata
    calculated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    calculated_by VARCHAR(36), -- User or system
    calculation_version VARCHAR(10), -- Version of calculation algorithm
    
    -- Foreign Keys
    FOREIGN KEY (video_id) REFERENCES videos(id) ON DELETE CASCADE,
    
    -- Indexes
    INDEX idx_quality_video_type (video_id, metric_type),
    INDEX idx_quality_grade (quality_grade),
    INDEX idx_quality_vru_type (vru_type),
    INDEX idx_quality_calculated (calculated_at),
    INDEX idx_quality_threshold (threshold_passed)
);
```

## 6. User Workflow Specifications

### 6.1 Automated Ground Truth Generation Workflow
1. **Video Upload**: User uploads video to system
2. **Processing Queue**: System queues video for ground truth generation
3. **Model Selection**: System selects appropriate model based on video content
4. **Frame Processing**: System processes video frames through ML pipeline
5. **Detection Generation**: System generates bounding boxes and classifications
6. **Quality Check**: System runs automated quality checks
7. **Review Queue**: Generated detections added to review queue
8. **Notification**: User notified that ground truth is ready for review

### 6.2 Manual Validation Workflow
1. **Assignment**: Validator assigned to video or project
2. **Review Interface**: Validator opens video in review interface
3. **Frame Navigation**: Validator navigates through frames with detections
4. **Detection Review**: Validator examines each detection for accuracy
5. **Corrections**: Validator corrects bounding boxes or classifications if needed
6. **Quality Marking**: Validator marks difficult/occluded/truncated cases
7. **Approval/Rejection**: Validator approves or rejects each detection
8. **Progress Tracking**: System tracks validation progress
9. **Completion**: Validator marks section/video as complete

### 6.3 Quality Assurance Workflow
1. **Metric Calculation**: System calculates quality metrics periodically
2. **Threshold Checking**: System checks metrics against quality thresholds
3. **Issue Identification**: System identifies potential quality issues
4. **Alert Generation**: System generates alerts for quality problems
5. **QA Review**: Quality assurance team reviews flagged issues
6. **Corrective Action**: Issues are corrected or marked as acceptable
7. **Metric Update**: Quality metrics are recalculated after corrections
8. **Reporting**: Quality reports generated for project stakeholders

### 6.4 Export and Training Workflow
1. **Export Request**: User requests dataset export for ML training
2. **Filtering**: System applies filters (validation status, classes, etc.)
3. **Dataset Split**: System creates train/validation/test splits
4. **Format Conversion**: System converts to requested format (COCO, YOLO, etc.)
5. **Quality Validation**: System validates export completeness and quality
6. **Package Creation**: System packages dataset with metadata
7. **Download Preparation**: System prepares download link or transfer
8. **Notification**: User notified that export is ready
