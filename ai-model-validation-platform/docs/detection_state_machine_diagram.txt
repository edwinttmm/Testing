## Critical Timing Constraints

```
┌──────────────────────────────────────────────────────────────┐
│              TIMING CONSTRAINT HIERARCHY                      │
└──────────────────────────────────────────────────────────────┘

1. GRACE_PERIOD (Outermost Filter)
   ├─ Default: 2000ms (2 seconds)
   ├─ Window: [video_start - 2s, video_end + buffer]
   └─ Rejects: Detections outside this window

2. DEBOUNCE (Primary Bottleneck) ⚠️ CRITICAL
   ├─ Default: 100ms
   ├─ Enforces: Minimum gap between "threshold_cross" events
   ├─ Maximum Rate: 1000ms / 100ms = 10 Hz
   └─ For 5s video: 10 Hz × 5s = 50 events maximum

3. STEADY_HIGH_INTERVAL (Alternative Path)
   ├─ Default: 5ms
   ├─ Allows: 200 Hz sampling during "high" state
   └─ Event Type: "steady_high" (not "threshold_cross")

4. CONTINUOUS_INTERVAL (Continuous Mode)
   ├─ Default: 5ms
   ├─ Allows: 200 Hz continuous sampling
   └─ Event Type: "continuous" (not "threshold_cross")

┌──────────────────────────────────────────────────────────────┐
│                    RATE LIMITING ANALYSIS                     │
└──────────────────────────────────────────────────────────────┘

Expected Input:
  └─ 200 Hz sampling × 5s video = 1000 samples
       ↓
  [Voltage Threshold Filter]
       ↓
  800-1000 voltage crossings (assuming signal crosses threshold)
       ↓
  [Video Window Filter: 2s grace period]
       ↓
  ~700-900 detections within window
       ↓
  [Debounce Filter: 100ms minimum gap] ⚠️ BOTTLENECK
       ↓
  Maximum: 10 Hz × 5s = 50 events
       ↓
  Actual: 4 events (8% of maximum)

Conclusion: Only 4 detections had >=100ms gap between them
```


### When State is Updated
```

```

### When State is Cleared
```

  ↓

```

### State Race Condition Prevention
```
Lines 1780-1782 (Comments):
"REMOVED: last_detection_times update (now done atomically in _should_record_detection)"
"This prevents duplicate detection race condition by ensuring check-and-update is atomic"
"The update happens in _should_record_detection() inside the same lock as the check"
```

**Key Insight**: State update is atomic with the debounce check, preventing race conditions where multiple threads could record the same detection.

**Key Insight**: The 4 events represent a sparse detection pattern where voltage crossings happened to be spaced exactly 100ms apart, possibly due to:
- Signal characteristics (periodic pulses at 10 Hz)
- Previous test state not cleared
- Video timing misalignment causing most detections to fall outside window
- Actual voltage signal had only 4 distinct rising edges
