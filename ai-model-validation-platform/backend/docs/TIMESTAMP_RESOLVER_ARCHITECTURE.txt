┌──────────────────────────────────────────────────────────────────────────┐
│  TimestampVideoResolver.validate_video_assignment()                      │
└──────────────────────────────────────────────────────────────────────────┘
                              │
                              │
            ┌─────────────────▼─────────────────┐
            │ _get_video_timing_windows()       │
            │ (Query SequenceVideoResult)       │
            └─────────────────┬─────────────────┘
                              │
                              │ SQL Query (2-3ms)
                              ▼
            ┌─────────────────────────────────────────────────┐
            │  SELECT svr.video_id,                           │
            │         svr.video_start_time,                   │
            │         svr.video_end_time,                     │
            │         svr.sequence_order,                     │
            │         v.filename, v.duration                  │
            │  FROM sequence_video_results svr                │
            │  JOIN videos v ON svr.video_id = v.id          │
            │  WHERE svr.video_sequence_id = :sequence_id     │
            │  ORDER BY svr.sequence_order                    │
            └─────────────────┬─────────────────────────────┘
                              │
                              │ Returns: List[VideoTimingWindow]
                              ▼
            ┌─────────────────────────────────────────────────────┐
            │ Video Timing Windows (In-Memory)                    │
            │ ─────────────────────────────────────────────       │
            │                                                      │
            │ Window 1: [10.0, 25.0)  video_id="vid1"            │
            │ Window 2: [25.0, 40.0)  video_id="vid2"  ← Match!  │
            │ Window 3: [40.0, 55.0)  video_id="vid3"            │
            └─────────────────┬───────────────────────────────────┘
                              │
                              │
            ┌─────────────────▼─────────────────┐
            │ _find_video_by_timestamp()        │
            │ (Linear search with buffer logic) │
            └─────────────────┬─────────────────┘
                              │
                              │ detection_timestamp = 12.5
                              │
                ┌─────────────▼──────────────┐
                │ Check Window 1:            │
                │ 10.0 <= 12.5 < 25.0? ✅    │
                │ Return: "vid1"             │
                └────────────────────────────┘


================================================================================
EDGE CASE HANDLING
================================================================================

1. DETECTION BEFORE FIRST VIDEO
─────────────────────────────────

    Timeline:
    ├───────────┤───────────────────────────────►
    9.95        10.0 (video1 starts)
    ↑
    Detection (50ms early)

    Logic:
    • Within 100ms buffer? ✅
    • Assign to first video
    • Log warning

2. DETECTION DURING TRANSITION
───────────────────────────────

    Timeline:
    ───────────[video1]───────────────[video2]─────────►
              24.95  25.0  25.05  25.1
                      ↑
                 Detection (in 50ms gap)

    Logic:
    • Check transition buffer (100ms)
    • Assign to next video
    • No "video not found" error

3. DETECTION AFTER LAST VIDEO
──────────────────────────────

    Timeline:
    ─────────────[video3]───────────────►
                        50.0  50.2
                              ↑
                         Detection (200ms late)

    Logic:
    • Beyond buffer (>100ms)? ❌
    • Return None
    • Log warning

PERFORMANCE CHARACTERISTICS
================================================================================

┌────────────────────────────────────────────────────────────┐
│  Operation Timing Breakdown                                │
└────────────────────────────────────────────────────────────┘

    validate_video_assignment()
    │
    ├─ [1-2ms] SQL Query (SequenceVideoResult + Video)
    │          - Uses indexes: idx_seq_video_result_sequence
    │          - Returns ~2-10 rows typically
    │
    ├─ [0.5ms] Build VideoTimingWindow objects
    │          - In-memory allocation
    │          - O(n) where n = video count
    │
    ├─ [0.5ms] Linear search through windows
    │          - O(n) comparison (n typically <10)
    │          - Early exit on match
    │
    └─ [1ms]   Logging and result construction
               ──────────────────────────────────
               TOTAL: 2-4ms per detection


Memory Usage:
─────────────
• Per-session cache: ~200 bytes per video
• Typical: 5 videos × 200 bytes = 1KB
• Max: 100 videos × 200 bytes = 20KB

───────────────────────────

    1. Query SequenceVideoResult WHERE video_sequence_id = "seq-123"

    3. Check: 10.0 <= 12.5 < 25.0? ✅
    4. Return: "vid1"


================================================================================
VALIDATION MODES
================================================================================

PHASE 1: VALIDATION-ONLY (Current)
───────────────────────────────────

    Metadata (Primary)  ──┐
                          ├─► Compare ──► Log Mismatch
    Timestamp (Audit) ────┘

    • No changes to production logic
    • Collect mismatch statistics
    • Prove reliability

PHASE 2: FAILOVER MODE
──────────────────────

    Metadata ──► Success? ──Yes──► Use metadata
                    │
                    No
                    │
                    ▼
              Timestamp ──► Use timestamp

    • Timestamp as backup
    • Prevents NULL video_id

PHASE 3: AUTHORITATIVE MODE
────────────────────────────

    Timestamp (Primary)  ──┐
                           ├─► Compare ──► Log if differs
    Metadata (Audit) ──────┘

    • Timestamp is source of truth
    • Metadata for validation only
    • Maximum accuracy

================================================================================
KEY DECISION POINTS
================================================================================

WHY TIMESTAMP-BASED?
────────────────────
• Authoritative: Based on actual playback timing
• Reliable: Not dependent on metadata updates
• Verifiable: Can be validated against recorded events

WHY NOT REPLACE METADATA IMMEDIATELY?
──────────────────────────────────────
• Risk mitigation: Validate first, change later
• Data collection: Measure mismatch rate
• Confidence building: Prove reliability over time

WHY SEQUENCEVIDEORESULT TABLE?
───────────────────────────────
• Already has video_start_time and video_end_time
• No schema changes required
• Performant with existing indexes
